## What's Changed

**Several Claude logins.** A hub now holds named Claude logins, each refreshed on its own, and every loop runs on the one it names. Settings lists the hub's logins and adds each; New loop and the loop page choose and show a loop's login; the Fleet page shows each login's plan usage, and the plan cap sleeps only the loops on the login that is over. (#925, #926: PRs #1148–#1178, #1229, #1236)

**Cloud loops reach their repo.** A cloud loop starts from its own GitHub repo, in a claude.ai environment of its own, through Claude's GitHub App (ADR-0061). The hub's token for the loop is a network secret on that environment, so it never enters the VM; the loop's page walks the setup (script, hub address, token with Rotate) and checks that the hub hears from the loop. Only the loop's own session reaches the hub, and only during a turn. (#1168, #1179: PRs #1185, #1190, #1214, #1218, #1226, #1233)

**Fixes.**
- A message that reached a loop just before its process was killed is said again to the next session, instead of being dropped; a message the hub gives up on after three crashed turns shows in the loop's timeline. (#1189, PRs #1206, #1208)
- Two images sent together in Telegram reach the loop as one message. (#1199, PR #1211)
- The first-run page's Loops card names the loop whose wake failed, and how. (#1197, #1198, PRs #1209, #1210)
- Settings says which login a check ran on, so a bare hub no longer shows one login as both signed in and refused. (#1203, #1212, PRs #1216, #1221)
- The workstation image checks the fingerprint of Anthropic's apt signing key and pins the Claude Code version a release ships. (#1200, #1223, PRs #1222, #1234)

**Breaking for API users.** The single-login routes and plan usage's top level are gone; the control room reads plan usage from logins alone (#1077, PR #1178).

## Upgrading

Run `sudo spool upgrade v0.6.2` from v0.6.0 or v0.6.1. From v0.5.1, follow [docs/OPERATIONS.md → Upgrading](https://github.com/enes-alatas/spool/blob/v0.6.2/docs/OPERATIONS.md#upgrading) by hand.

A cloud loop created before this release is held with a problem until its repo and environment are set on its page; the shared environment under Settings → Cloud is no longer the start's source.

**Full Changelog**: https://github.com/enes-alatas/spool/compare/v0.6.1...v0.6.2
