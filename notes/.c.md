### Current behavior and friction

Deleting a cloud loop removes it from the hub, but its session on claude.ai keeps the values of every env variable it was handed until the operator archives the session there (#1024, ADR-0059 item 10). The delete confirm still talks about a worktree, which a cloud loop has none of, and never tells the operator the values outlive the loop.

### Coupling points

The loop delete confirm in `web/src/` (the browser's own confirm box, so no shot); `GET /api/loops/{name}/connections` already lists the loop's attached connections.

### Seams / ADRs touched

ADR-0059 item 10.

### Proposed shape

For a cloud loop the confirm names its attached env variables and says their values stay in the session until it is archived on claude.ai, so rotate them if the loop misbehaved. With none attached, it asks to archive the session instead. The worktree sentence goes for cloud loops.

The problem label (#1030), the connection page (#1031).
