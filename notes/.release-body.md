## Cloud loops, users, and one Claude login

325 commits since v0.5.1. Binaries for linux and darwin (amd64, arm64) with `SHA256SUMS` and build attestations are attached; the images are published by digest below.

### Cloud loops (ADR-0056, ADR-0059)
A loop can now run in a Claude Code cloud session beside the contained loops.
- Create a cloud loop from New loop; it wakes in a cloud session driven through the `claude` CLI.
- Settings → Cloud is a guided setup: the cloud listener switch, the public address check, the Claude account sign-in with the CLI's own login, and the shared environment picked by name with the egress allowlist to paste and confirm.
- Each cloud session gets a hub token of its own, revoked at a stop. A stopped cloud loop's page says a turn may still be running and links the session.
- A cloud session is handed its loop's env-var connections as it starts; the room says when a connection change reaches a cloud loop, and deleting a cloud loop names the secrets a session keeps.
- A cloud turn's cost is the hub's estimate, shown as such or as unknown.
- A held cloud loop reads "needs setup"; a cloud loop warns while its allowlist isn't confirmed.

### One Claude login (ADR-0058)
- Contained loops reach the model through the hub's Claude proxy on one claude.ai login, signed in from first run or under Settings → Claude login. It supersedes the setup-token, refreshes before it expires, and Sign out revokes it.
- A hub with no `claude` of its own signs in with the workstation image's.

### Users, roles and sign-in (ADR-0048, ADR-0050, ADR-0051)
- The control room has users with passwords and sessions. The first start creates `admin`; `spool user` manages users; roles bound what a user may call and see.
- Users link their Telegram or Slack account under Settings → Account. A link code is the one way a person becomes an allowed sender. An owner sees links, blocks users, and manages users from Settings.
- A loop's owner is chosen as a user, and the room shows who created and changed a loop.
- The first-run page can be finished without a chat surface.

### Private conversations (ADR-0049)
- Every allowed sender holds a private conversation with a loop (`dm:<name>`). A loop's page shows the conversations the reader may read; a linked user reads the ones that are theirs.

### Corrections (ADR-0055)
- An edited or deleted Telegram or Slack message reaches its loops as a correction; a message still waiting is corrected in place; the room shows the edit beside the message.

### Loop health (ADR-0053)
- The control room shows a loop's open problems, and the owner is told once when a loop keeps failing or its workstation stays down.
- A loop says what it is working on with a `[doing: …]` trailer; the Fleet row and the loop page show it.

### Connections
- A `github-app` connection: the hub holds the app's key and mints hour-long installation tokens. A loop's git and gh fetch them through the `spool-github` helper and never see the key.

### Loop controls
- A loop can be set to work alone (the Agent tool is denied).
- A per-loop daily USD cap sleeps the loop until the day turns.
- Plan usage only rises within a window, with its reset fixed.

### Install, upgrade, backup (ADR-0052, ADR-0057)
- A tag builds and attaches the binaries with checksums and attestations and publishes the images by digest. The hub never pulls; `spool images` says how to fetch a release's images.
- `spool upgrade` upgrades the hub a systemd unit runs, with backup and rollback; `spool migrations` lists a build's migrations.
- Backup and restore scripts cover the data directory and the workstation volumes.

### Security hardening
- Each workstation gets its own network and no NET_RAW; the hub warns at boot on an engine that lets DNS past the wall.
- The egress allowlist refuses an IPv4 literal and a one-label domain, and reads `*.example.com` as `.example.com`.
- `spool-hook` refuses a gh or git call that carries a credential, and kills that would reach other loops' processes.
- The operator listener bounds what a caller can make it hold; the loop listener closes idle connections; members read no connection config and no pairing code.
- Toolchain go1.26.10 (GO-2026-6809).

### Control room polish
- Settings → Egress is a dialog with a filtered list; copy chips for the literals an operator types; round loop controls; the mission is edited in a dialog; web addresses are links; a Fleet row shows its loop's mission.
- The README demo video shows the room as it ships, and "Where loops run" shows a cloud loop running.

## Upgrading from v0.5.1
- By hand, this once: v0.5.1 has no `spool upgrade`, so follow [docs/OPERATIONS.md → Upgrading](https://github.com/enes-alatas/spool/blob/v0.6.0/docs/OPERATIONS.md#upgrading).
- The new admin's one-time password goes to stdout, which the unit discards: run `spool user reset admin`.
- The setup-token keeps working until an admin signs in under Settings → Claude login; that sign-in replaces it. Cloud loops need the sign-in.
- No re-linking: senders allowed before the upgrade keep working and keep their loops. A person links under Settings → Account only before they are chosen as a loop's owner.
- A stored egress host the new allowlist refuses is removed under Settings → Egress.

## Known issue
- `spool upgrade` on v0.6.0 refuses every release (#1149): its parser rejects the header `spool images` prints. It fails safe and nothing is changed. The fix is on main and ships in v0.6.1.
