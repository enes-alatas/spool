### Current behavior and friction

A change to a connection reaches a contained loop at its next turn. A cloud loop gets its env variables only when its session starts (#1024), and an MCP server never reaches a cloud session at all. The connection page lists the loops a connection is attached to without saying this, so an operator who edits a value expects a cloud loop to pick it up and it doesn't.

### Coupling points

The connection page's attached-loops list and its lede (`web/src/`); loops carry `runtime`, so no new API field.

### Seams / ADRs touched

ADR-0043 item 5 (its 2026-10-07 amendment), ADR-0059 item 10.

### Proposed shape

Beside each cloud loop on a connection's page: an env variable says the change reaches it at its next start, with a tooltip saying to pause and resume the loop to apply it now; an MCP server says it never reaches the loop. The page's lede says the same in one sentence. Iris's shots 3 and 4 on issue 1023 (comment 6325760198) show it.

### Out of scope

The problem label (#1030), the delete dialog (#1032).
