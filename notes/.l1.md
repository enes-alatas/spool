### Problem statement

On a docker hub the Claude sign-in for cloud loops cannot run: the CLI lives in the workstation image, not on the host, and that container's egress allows no sign-in host (ADR-0056 item 6, ADR-0058 item 5). An operator running the hub in docker therefore has no way to sign the hub into Claude for cloud loops. Split out of #864 (its parts 1–3 shipped; operator decision of 2026-10-23 to file the leftovers on their own).

### Coupling points

The sign-in container's egress (the shape is Elliot's: which hosts, through which proxy, for the sign-in's duration only), `internal/httpapi` settings routes that start the sign-in, OPERATIONS "Cloud loops".

### Seams / ADRs touched

ADR-0058 item 5, ADR-0028 (egress), ADR-0056 item 6.

### Proposed shape

Elliot posts the egress shape on this issue first; then one PR that runs the sign-in in a container with that egress and nothing else, with a tier-2 case on the docker runtime.
